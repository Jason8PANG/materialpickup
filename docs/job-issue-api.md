# 工单发料接口（Job Issue API）

> **面向对象**：需要通过 HTTP 接口把线边仓线材「按工单发料」的外部系统，以及学习后要独立完成集成的 AI 助手。
>
> 本文只写对外契约：URL、鉴权、请求体、响应、错误码、业务前提。照着本文即可完成对接，**不需要了解服务端内部实现**。

---

## 1. 接口说明

一句话：**把线边仓里指定物料、指定批次的指定数量，按工单调拨/发料记账**——库存扣减，工单该物料的已发数量增加。

一次成功调用 = 一条发料明细。

**适用场景**

| 场景 | 说明 |
| --- | --- |
| 车间按工单领用线材 | 上游系统（MES / 报工 / 消耗登记）直接发起工单发料 |
| 裁线、上机消耗需冲减工单物料 | 消耗量按工单记账 |
| 实物已在线边仓，需要转成 ERP 账面发出 | 常见于线边仓备料完成后 |

**不适用**：库位之间的库存搬移、采购入库、退料（均走其他接口）。

## 2. 请求

### 2.1 基本信息

| 项 | 值 |
| --- | --- |
| URL | `POST /api/external/job-issue` |
| 方法 | `POST` |
| Content-Type | `application/json; charset=utf-8` |
| 成功状态码 | **`201`**（注意不是 200，判断请用 2xx） |

### 2.2 请求头

| Header | 必填 | 说明 | 示例 |
| --- | --- | --- | --- |
| `X-API-Key` | 是 | 调用凭证，向接口维护方索取 | `NAI-WIPTRACK-2026` |
| `X-Site-Ref` | 是 | 站点标识，只接受 `310`、`410` | `410` |

站点取值：`310` = 苏州工厂，`410` = 槟城工厂。缺省或取值非法直接返回 `400`。

### 2.3 请求体（JSON）

| 字段 | 类型 | 必填 | 示例 | 说明 |
| --- | --- | --- | --- | --- |
| `job` | string | 是 | `ENG0001317-0000` | 工单号 |
| `item` | string | 是 | `WIRE-24AWG-RED` | 物料号 |
| `lot` | string | 是 | `LOT20261021A` | 批次号，须与线边仓现存批次一致 |
| `unit` | string | 是 | `EA` 或 `FT` | 单位 |
| `submitter` | string | 是 | `zhangsan` | 提交人，写入记录便于追溯 |
| `quantity` | number | 是 | `12.5` | 发料数量，必须 > 0，最多 4 位小数；超出 4 位小数按四舍五入截断，整数值按整数保存 |
| `documentNumber` | string | 否 | `ENG0001317-0` | 单据号，≤ 12 位；不传或为空时自动取 `job` 的前 12 位 |

**不要传库位参数**：发料库位由服务端固定为**线边仓**，请求里传了也不会生效。

```json
{
  "job": "ENG0001317-0000",
  "item": "WIRE-24AWG-RED",
  "lot": "LOT20261021A",
  "unit": "FT",
  "submitter": "zhangsan",
  "quantity": 12.5,
  "documentNumber": "ENG0001317-0"
}
```

## 3. 响应

### 3.1 受理成功 —— `201`

```json
{
  "success": true,
  "id": 10231,
  "documentnumber": "ENG0001317-0",
  "message": "已入队"
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `success` | bool | 固定 `true` |
| `id` | number | 本次发料记录 ID，后续查询/沟通用这个号 |
| `documentnumber` | string | 本次实际生效的单据号（未传时是 `job` 的前 12 位，注意小写 `n`） |
| `message` | string | 固定 `"已入队"` |

> ⚠️ **返回成功 = 已受理入队，不等于 ERP 已记账。** 实际扣账由后台异步完成，通常在数秒内。失败会在看板「同步接口查询」页显示并触发告警。

### 3.2 重复提交 —— `200`

```json
{
  "success": true,
  "duplicated": true,
  "id": 10231,
  "message": "已存在相同发料记录，未重复入队"
}
```

判定为重复的键：`(站点, documentNumber, job, item, lot)` 完全相同，且原记录仍在生效（已受理、处理中或已成功）。此时**不会重复入队、不会重复扣账**，`id` 是已有记录的 ID。

### 3.3 鉴权失败 —— `401`

```json
{ "success": false, "error": "API Key 无效" }
```

> ⚠️ **字段名是 `error`，不是 `message`**。401 与其余错误码的字段名不一致，客户端两个都要读。

### 3.4 参数错误 —— `400`

```json
{ "success": false, "message": "缺少必填项：job、item" }
```

```json
{ "success": false, "message": "quantity 必须为数字且大于0" }
```

```json
{ "success": false, "message": "documentNumber 超过 … 长度 12" }
```

```json
{ "success": false, "message": "缺少或无效的站点标识（X-Site-Ref），可选站点: 310, 410" }
```

- 缺必填项时，`message` 会列出**实际缺失**的字段（如只缺 `lot`、`unit`）。
- 400 / 500 的说明字段统一叫 `message`。
- 单据号超长的原文中含平台简称（上例用 `…` 代替），匹配时认 `documentNumber` 与 `12` 即可。

## 4. 调用示例

> 示例里的物料号 `WIRE-24AWG-RED`、批次 `LOT20261021A`、工单 `ENG0001317-0000` 都是**示例值**，实际请替换为你自己的真实数据；`<host>` 是看板服务地址，向接口维护方索取（不同环境不同）。

### 4.1 curl

```bash
curl -X POST "https://<host>/api/external/job-issue" \
  -H "Content-Type: application/json; charset=utf-8" \
  -H "X-API-Key: NAI-WIPTRACK-2026" \
  -H "X-Site-Ref: 410" \
  -d '{
    "job": "ENG0001317-0000",
    "item": "WIRE-24AWG-RED",
    "lot": "LOT20261021A",
    "unit": "FT",
    "submitter": "zhangsan",
    "quantity": 12.5,
    "documentNumber": "ENG0001317-0"
  }'
```

### 4.2 Python（requests）

```python
import requests

URL = "https://<host>/api/external/job-issue"
HEADERS = {
    "Content-Type": "application/json; charset=utf-8",
    "X-API-Key": "NAI-WIPTRACK-2026",
    "X-Site-Ref": "410",
}
PAYLOAD = {
    "job": "ENG0001317-0000",
    "item": "WIRE-24AWG-RED",
    "lot": "LOT20261021A",
    "unit": "FT",
    "submitter": "zhangsan",
    "quantity": 12.5,
    "documentNumber": "ENG0001317-0",
}

resp = requests.post(URL, json=PAYLOAD, headers=HEADERS, timeout=15)
body = resp.json()

if resp.ok:                                  # 201 新受理 / 200 重复
    print("记录ID:", body["id"], "重复:", body.get("duplicated", False))
else:
    # 401 用 error，400/500 用 message
    print("失败:", resp.status_code, body.get("message") or body.get("error"))
```

### 4.3 成功与失败对照

| 情况 | HTTP | 关键字段 | 你的动作 |
| --- | --- | --- | --- |
| 首次提交成功 | `201` | `id`、`documentnumber` | 记录 `id`，等后台过账 |
| 重复提交 | `200` | `duplicated: true`、`id` | 视为成功，不要换号重发 |
| 参数/站点/数量问题 | `400` | `message` | 按文案改数据后重提 |
| 凭证错误 | `401` | `error` | 检查 `X-API-Key` |
| 服务端异常 | `500` | `message`（技术信息） | 不要自动重试，联系维护方 |

## 5. 业务规则与前置条件

调用前逐条确认，否则会被业务校验拒绝：

- [ ] **实物已在线边仓**：线材必须先完成入库/转到线边仓，本接口只做「线边仓 → 工单」的账面发出。
- [ ] **工单存在**，且该物料**剩余可发量 ≥ quantity**。
- [ ] **批次号与线边仓库存一致**：`lot` 必须是线边仓现存批次，注意大小写与前后空格。
- [ ] **`quantity` > 0，最多 4 位小数**。
- [ ] **`documentNumber` ≤ 12 位**，同一站点内保持唯一（建议用「工单号 + 流水」）。
- [ ] **不指定库位**：发料库位固定为线边仓。

## 6. 幂等与重试

| 场景 | 能否重试 | 做法 |
| --- | --- | --- |
| 同一条数据重复提交 | 可以 | 直接重提，返回 `duplicated: true`，不会重复扣账 |
| 网络超时 / 无响应 | 可以 | 原样重提（幂等键相同，不会重复入队），再用返回的 `id` 核对 |
| `400` 参数错误 | 修正后重试 | 按 `message` 改数据 |
| `401` | 修正后重试 | 补正 `X-API-Key` / `X-Site-Ref` |
| 业务拒绝（数量不足、库存不足） | **不要盲目重试** | 先改数据（补库存、改数量、换批次），再重提 |
| 单据号冲突 | **不要重试** | 需人工核对单据号是否重复，确认后换 `documentNumber` 重提 |
| `500` 服务端异常 | **不要自动重试** | 联系维护方，用 `documentNumber` 排查是否已受理 |

要点：幂等键 = `(站点, documentNumber, job, item, lot)`。**换 `documentNumber` 就是一条新记录**，会真的再扣一次账——只有确认上一笔未生效或已作废时才换号。

## 7. 错误处理对照表

| HTTP | 说明文案（原文） | 原因 | 建议动作 |
| --- | --- | --- | --- |
| `401` | `API Key 无效`（字段 `error`） | `X-API-Key` 缺失或错误 | 补正凭证，勿重试空请求 |
| `400` | `缺少或无效的站点标识（X-Site-Ref），可选站点: 310, 410` | 站点缺失或不在 310/410 | 传正确站点 |
| `400` | `缺少必填项：job、item` | 必填字段为空（文案列出实际缺失项） | 补齐字段 |
| `400` | `quantity 必须为数字且大于0` | 数量非数字、≤0、或空 | 传正数，最多 4 位小数 |
| `400` | `documentNumber 超过 … 长度 12` | 单据号超长 | 截到 12 位内，或留空自动取工单号前 12 位 |
| `400` | `站点 {站点} 未配置发料仓库` | 该站点未开通发料（310/410 均已配置，正常不会出现） | 联系维护方 |
| `500` | 写入失败等技术信息 | 服务端异常 | 记录 `documentNumber` 与时间，联系维护方 |

**业务拒绝**（HTTP 层可能是 2xx，错误出现在后续过账环节，请看板「同步接口查询」页的实际结果）：

| 现象 | 业务含义 | 建议动作 |
| --- | --- | --- |
| 本次要发的数量比工单还能发的数量多 N | 工单该物料剩余可发量不足 | 减少数量，或先核对工单需求量 |
| 转移数量 X 大于批次存货 N | 线边仓该批次库存不足 | 补库存 / 确认批次号 / 拆分数量 |
| 单据号相关报错 | 单据号冲突 | 人工核对，确认后换 `documentNumber` 重提 |

## 8. FAQ

**Q1：接口返回成功了，但 ERP 里没看到扣账？**
接口成功只代表**已受理入队**，扣账由后台异步完成，通常数秒内。超过 5 分钟仍未过账，到看板「同步接口查询」页用 `id` 或 `documentNumber` 查该笔的执行结果；那里会显示失败原因并已触发告警，把该页信息发给维护方最快。

**Q2：报「本次要发的数量比工单还能发的数量多 N」怎么办？**
工单该物料的剩余可发量不够了。把 `quantity` 降到 N 以内，或先在 ERP 核对工单需求量是否要调整。**不要原样重试**。

**Q3：报「转移数量 X 大于批次存货 N」怎么办？**
线边仓这个批次的库存不足。依次检查：批次号是否写错（大小写/空格）→ 实物是否真的已经入了线边仓 → 数量是否超出该批次库存。补足库存后再提。

**Q4：能不能指定从别的库位发料？**
不能。发料库位固定为**线边仓**，接口不接受库位参数。需要从其他库位出料时，先把库存转到线边仓，再调用本接口。

**Q5：同一个单据号可以反复提交吗？**
可以。相同 `(站点, documentNumber, job, item, lot)` 会返回 `duplicated: true` 且不重复入队。但**换一个 `documentNumber` 就是新记录，会再扣一次账**，别用它来"试试看"。
